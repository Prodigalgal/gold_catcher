# AI 席位与兜底模型

0.11.0 起，研究、裁决、压缩及其兜底均只允许 MIMO、GLM、LongCat、MiniMax、Grok。Arena、DeepSeek、QWEN 不再作为可执行提供商。旧配置迁移时移除名单外提供商和兜底，保留原加密历史版本与研究证据。

每席可在 UI 选择一个备用模型和独立上下文、输出、超时预算。开启兜底时页面默认选择 LongCat Flash。备用路线仍受阶段和整轮剩余期限约束，最多一层；目录存在不能证明推理可用。长短线和压缩使用独立执行槽。`grok` / `grok_web` 视为同一厂商。

下文为 0.5.0 的历史实现记录，其中默认 Arena、DeepSeek 和 300 秒上限已不适用于当前版本。当前请求超时上限为 900 秒。

## 0.5.0 历史记录（已停用默认路由）

0.5.0 为短线三席研究、三席裁决、长线三席研究、三席裁决和前置信息压缩分别配置一个兜底模型，默认均为 `arena/Max`。主模型仍为原来的 MIMO、DeepSeek、Grok，压缩主模型仍为 MIMO。配置界面可以修改每个兜底的提供商、模型、上下文预算和请求超时，也可关闭兜底；提供商端点与密钥使用已有的加密配置机制。

旧的当前配置升级为新的配置版本，加入 Arena 提供商和每席兜底；历史配置不增加兜底，已有研究继续按冻结版本恢复。修改后的配置不会在下一次启动时被默认值覆盖。摘要协议与原文哈希没有改变，已经完成的摘要不因添加兜底被全部重做。

主模型不可用、凭据被拒绝、网络或响应超时、上下文不足或输出校验失败时，释放主模型执行位并尝试兜底。切换只允许一层。兜底重新检查自己的模型目录、凭据和上下文预算，使用同一份冻结材料；不同模型实际收到的打包内容和预算分别归档。超时后继续接收未完成正文、或绕过兜底的校验，均不算有效输出。

每个 HTTP 请求仍最多使用其配置时长（上限 300 秒）。一次主模型加兜底可以消耗两者时长之和，但受当前阶段、整轮研究或压缩任务剩余期限限制。取消、阶段封存和执行期限耗尽后不会再启动兜底。研究已通过的席位不重做；引用和候选校验失败后的修复重试可直接使用该席兜底。

Arena 在本系统最多并发三席，默认值可通过 `GOLD_AI_ARENA_CONCURRENCY` 下调。每席发起独立请求，采用新的上下文和匿名候选。`arena/Max` 为随机模型路由，不假定每次必然抽到不同底层模型；上游返回的模型标签、请求目标、切换原因和主模型失败输出都保留在聊天和审计记录中。

裁决仍要求至少三个不同席位的有效结果，严格多数采纳同一完整候选。可以由多席各自使用 Arena Max 兜底；审计记录显示兜底席数和上游报告的模型标签数量。重复提交同一席不会增加票数。Java 计算、成本与内部成交规则不变，过期研究继续分析但不能生成内部订单。

验证覆盖：主模型目录不可用、错误输出归档后切换、取消不切换、阶段期限不延长、共享 Arena 的六席准入和三请求并发、旧配置迁移与恢复、三席随机路由裁决与重复席拒绝。上线验收还需验证真实 Arena 响应，配置成功不能替代上游可用性证明。
