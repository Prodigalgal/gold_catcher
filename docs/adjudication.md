# 三模型研究与裁决

0.4.5，2026-10-11。短线和长线默认使用同一组三个模型；可在运行页修改端点、提供商、模型与预算：

| 厂商 | 辩论、裁决模型 | 前置压缩 |
| --- | --- | --- |
| MIMO | `mimo/mimo-v2.6-pro` | `mimo/mimo-v2.6-flash` 独立压缩请求 |
| DeepSeek | `deepseek/default` | 不承担 |
| Grok | `grok_web/grok-3` | 不承担 |

默认配置有三个参与决策的模型，每个分别承担辩论与裁决角色；界面上的三个研究角色和三个裁决角色不是六个不同模型。压缩请求不产生裁决票。每个周期通过 UI 配置三个研究者与三个裁决者，同一阶段必须来自不同提供商与不同底层模型。QWEN 仍被强制禁用，当前备用路线为空，不会自动切换到其他厂商。

## 阶段与上下文

独立研究、交叉质疑、修订各调用三个模型，首轮不读同伴，后两轮只读上一批已封存的有效结果。前三阶段仍要求至少两个有效结果才继续，失败、超时和迟到均单独显示。

最后一批同时向三个模型发送新的 system/user 上下文。各方看到同一冻结证据和同一批匿名修订，看不到其他模型本轮的裁决或其返回顺序。共同材料的阅读位置循环轮换；完整读取顺序和种子归档。研究与裁决复用模型明确标注，不声称这三个裁决者独立于先前研究，也不把不同模型视为统计独立。

每次请求独立检查字符、UTF-8 字节、网关输入估算、声明容量及输出预留。裁决回复只选择候选，不重复输出整份金融计划，减小输出和后续归档负担。MIMO 压缩继续使用自己的预算、缓存及截止时间，金融数值由 Java 计算并保留。

## 三方裁决规则

1. 每个裁决模型输出 `selectedCandidateId`，取值为本轮匿名修订消息 ID 或 `WAIT`，并给出理由、证据引用和两个周期的方向判断。
2. 裁决需要至少三个不同底层模型的有效结果。重复账号、路线或相同模型名不能形成额外一票；失败或迟到不计票。缺第三份有效裁决时记录 `LOW_QUORUM / INSUFFICIENT_VALID_JUDGE_OUTPUTS`，不调用模拟账本。
3. Java 以严格多数选择同一候选方案。三个有效裁决需要至少两票；若配置更多裁决者，门槛为有效人数的一半向下取整加一，不把四人平票算作多数。
4. 只复用修订阶段原方案的完整数值，不平均或拼接价格、数量、杠杆和退出条件。交易参数与风险、失效条件均相同的候选合并计票，十进制 `100` 与 `100.000`、未填与 null 不人为拆票。失效条件不同的方案保持分开；原方案和每条风险说明完整归档。
5. 三个不同选择或多数选择 WAIT 时，最终计划为 WAIT。裁决的多数票不是盈利概率，也不能覆盖行情、费用、产品规则、账户余额、总期限等 Java 校验。
6. 判决、每个模型的选择与理由、候选分组和少数意见写入 `adjudication`；聊天室显示裁决票、有效人数、门槛和原候选链接。历史单模型裁决记录按原样标注。

最终动作仍只进入内部模拟。裁决改变不了证据截止，迟到结果不能重写此前成交与账务。SHORT 默认总期限240秒、LONG默认900秒；超过总期限的研究为 EXPIRED，不能为了凑齐投票使用过期结论。

## 验收范围

Java 测试覆盖真实数值方案多数票、无多数 WAIT、两份有效裁决不得下单、重复模型不得加票、阅读顺序平衡、相同执行方案合票、错误候选 ID、额外裁决者平票及同一模型重复新闻判断不能制造共识。真实快照的全部阶段预算另行检查。

这些离线结果证明阶段与投票规则，不证明上游可用率、真实四阶段耗时或持续稳定性。线上记录需区分已选路线、实际有效回复、完整裁决及内部模拟账本结果。
