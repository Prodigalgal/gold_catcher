# 研究协议、重试和恢复

0.4.6，2026-10-11。所有流程仅用于内部模拟。

## 统一协议

研究输入统一为 `GOLD_RESEARCH_V1`：`protocol / evidence / phase / role / actorId / peers / execution`。冻结证据、Java数值和上轮有效消息采用相同字段；execution只描述请求时刻、尝试次数、交易过期状态及缺席者，不添加新行情。JSON与无损YAML仅是传输编码，预算模块选择更省字符的编码，字段含义、精度、ID和截止时间一致。

原生严格函数通道使用 `submit_research.arguments`；文本及模拟函数桥使用 `key=value` 行，避免模型组织大型JSON。Java将两者转为同一内部JSON结果，UI、投票、引用检查和账本使用该结果。兼容旧版有效JSON，原始回复仍归档。

```text
protocol=GOLD_RESEARCH_V1
title=形势观察
output=费用和确认不足，保持等待
shortDirection=UNKNOWN
longDirection=MIXED
quotedMessages=
evidenceRefs=market:quote,analysis:drivers
plan.action=WAIT
plan.riskAssessment=等待新证据
```

裁决输出 `selectedCandidateId=WAIT` 或一个修订候选ID，不生成金融计划。新闻判断使用 `impact.1.newsId / horizon / direction / reason / counter` 五字段，最多四组。MIMO压缩仅输出 `protocol=GOLD_COMPRESSION_V1` 和 `summary`，同样无需JSON，不计票。

值按单行书写，等号后可包含标点和其他等号。适配器兼容完全相同的重复字段/整段重复、与请求一致的phase回显、JSON字符串列表及impacts.N字段前缀。plan.reason在没有riskAssessment时映射为该说明，已有风险说明时保留到output，不丢掉叙述；有效JSON也采用同一转换。原文仍单独归档。

冲突字段/阶段、未知字段、缺必填项、坏列表、错误方向或不可核验引用会被拒绝。plan.action必须由模型明确提供；程序不推测WAIT、价格、数量、阈值或裁决票，数值字符串和ID原样保留，空/null表示未提供，`0`保留。风险说明120字、失效条件80字为硬限制，超长内容不会截断为一个可投票方案。

## 重试和期限

默认每席最多三次，含首次；只补失败席位，同一模型最多一票。超时、临时网络错误、408/425/429及指定5xx按2秒起步的指数退避加抖动重试，常规上限30秒。`Retry-After` 是下限，阶段不够时间则停止，绝不提前重试。凭据失效不会反复发送相同请求。

格式或引用错误交回同一模型，错误码标明缺动作、冲突字段、阶段不符、坏列表或超长的具体计划字段，反馈给出对应约束。重试仍只读原冻结证据与上轮封存观点，不看同阶段成功者；每次请求、无效回复、预算、编号和退避时刻归档。

| 默认设置 | SHORT | LONG |
| --- | ---: | ---: |
| 每阶段辩论预算 | 90秒 | 900秒 |
| 裁决预算 | 90秒 | 900秒 |
| 整轮执行上限 | 360秒 | 3600秒 |
| 冻结证据交易有效期 | 240秒 | 3600秒 |

这些是上限，成功回复立即推进。SHORT 使用独立 fast_lane（4–8 个轮次槽），整轮、阶段与交易有效期按UI配置分别冻结；默认阶段90秒、整轮360秒、交易有效240秒，单次请求最多120秒；MIMO关闭深度思考，支持映射的MiniMax请求使用none推理档，不调用慢速Arena兜底。LONG 使用独立 deep_lane（1–2 个轮次槽），单请求可配置至900秒，包括600秒长推理。相同产品的两周期可同时研究，同产品同周期不重复启动。供应商请求位和失败冷却按执行通道隔离，深度研究不占用短线请求位。

请求得到完整剩余预算，不为预留重试先除以尝试次数；阶段结束/取消会中断工作线程并取消HTTP Future，释放提供商请求位。UI可修改并发槽、模型和预算，下一轮生效；保存的阶段与整轮预算原样执行，不静默压小；请求级的短线120秒上限单独显示。既有研究保留原冻结设置。本地CONTEXT_INSUFFICIENT记录预算失败并禁止发送，不冷却未被调用的供应商。

每次HTTP尝试发送唯一X-Client-Trace-Id，收到响应头后立即记录X-Request-Id（兼容X-Any2API-Request-Id）。HTTP200仅为握手；event:error、error数据块、缺少结束标记或提前断流均记录FAILED。完整流和提交协议都通过后才记录VALIDATED_OUTPUT，格式失败不产生裁决票。两个ID和失败终态在聊天室审计中可查看。

早期缺席仍推进后续讨论，明确缺席者；修订候选不足两份时裁决只允许WAIT。最终必须取得至少三个不同模型的有效裁决，缺票记录LOW_QUORUM，不伪造裁决或订单。LONG交易过期后可继续完成裁决，记录 `COMPLETED_EXPIRED / NO_ORDER_STALE_EVIDENCE`；SHORT同样按整轮配置截止，并在交易有效期结束后禁止执行。过期、超时与缺票均不产生内部订单。后续事实不重写原证据或此前成交。

## 恢复与调度

成功回复、尝试和封存阶段落库。尚在执行期限内的研究重启后恢复缺失席位，不重复成功者或封存阶段，次数不清零。恢复使用原加密配置版本；原版本缺失/不匹配时明确FAILED_RECOVERY，不套用新端点或模型。运行期凭据使用稳定路由注册表，避免相等路由替换后弱引用键被GC清除；历史绑定保留至本进程结束，数据库仍仅保存加密密钥，公开接口不返回凭据。

当前后端单副本、Recreate部署；未声明多副本分布式执行能力。退出保留恢复检查点，金融动作与终态检查点同事务提交。自动启动失败短暂退避，不消耗成功研究的300/1800秒调度间隔。手动/自动共用执行位，行情、账本和原退出规则持续运行，升级保留调度开关。

## 0.4.7 正文压缩与上游恢复

近七日且在截止时刻已知的新闻构成完整候选池（数据库读取上限1000条），不再先截取最新12条。冻结时先选择不同信源组，再按新近补足，最终仍受每轮新闻数量和请求预算限制；商业RSS高频更新不能使较早的官方正文完全失去入选或压缩机会。时间未核验、未来发布、未来收到和隔离旧源仍排除。

后台压缩与deep_lane研究共用提供商请求位。仅深度通道MIMO的实际研究或等待请求阻止MIMO压缩，其他提供商等待期间可处理正文；新的深度MIMO请求中断压缩HTTP并优先取得请求位。fast_lane有独立请求位，不中断深度研究或压缩。已完成分块继续缓存，被打断的原始尝试保留，零分块完成记DEFERRED、已有分块记PARTIAL，10秒后可续做，不按上游故障累计退避。未完成全文合并的摘要不进入研究，完成晚于原截止时刻的摘要不改写原轮次。

信息集合页按当前分页批量读取摘要缓存，详情可切换原文和摘要，显示模型、更新时间、处理状态和分块进度；读取不调用模型。模型切换前的摘要仅作为标记的历史结果展示，正文变化后不把旧摘要标为当前；历史研究中看到的是该轮冻结结果。资讯来源选择可以在线持久化，停用来源不再进入新采集、压缩或研究候选，原始档案和历史研究仍可核对。

any2api的OPEN熔断状态只在实际请求尝试准入时推进，目录轮询不能使它自行恢复。仅非通用OpenAI端点、已入目录、OPEN、存在可用账号且最近探测状态READY的组合允许有限恢复尝试，预检标记MODEL_RECOVERY_READY，沿用单请求位、研究阶段期限、重试次数和冷却。FORCED_OPEN、无可用账号、探测失败或无这些运行元数据均不能获得例外；目录本身的available=false原样保留，不将其标成健康，也不产生虚构裁决。恢复尝试必须返回并通过正常输出校验才能计票。

文本协议忽略全空的新闻影响占位组；有内容但缺少newsId或字段不完整仍拒绝。引用数量和影响组错误会收到明确约束，金融参数、非空影响和引用不自动截断或猜补。

## 验收边界

本地测试验证文本/函数格式等价、数值精度、拒绝歧义、真实HTTP响应体超时、失败重试、缺票、过期继续裁决、事务回滚和恢复。生产公开快照检查所有阶段与格式修复的完整请求预算，不调用上游模型。线上完整研究、实际供应商重试和长期可用率需分别查看真实记录，不能用离线或UI样例替代。

## 0.4.8 收集后立即压缩与摘要准入

新闻正文、RSS 摘要和仅标题入库后通知独立压缩队列，另有两秒扫描恢复遗漏通知。原始文本不改写，正文与 feed 摘要采用不同 sourceTextHash / sourceFormat；不足600字符的短消息同样处理。尚未核实或未来发布时间可提前压缩，研究准入仍执行原有截止、发布时间与隔离检查。结构化行情、日历、经济值、指标和账本由 Java 提供，数值不经过生成式压缩。

UI 可选择压缩提供商、端点和模型，默认 MIMO Flash；QWEN 仍禁用，压缩角色永不计票。正在处理的任务冻结该次路由，新配置影响后续任务。缓存键包含来源、文本哈希、提供商/模型/端点/协议与压缩版本，提供商故障退避分别持久化。

下游只接收 cutoff 前完成的 EXTRACTED 摘要。失败、部分摘要、尚未完成或停用时，本轮不送入该条原文，newsCoverage 记录完成与未使用数量，聊天室保存对应准入记录。此规则替代0.4.7及更早的原文摘录兜底；旧研究继续保留原证据。

自动研究在实际 start 冻结行情前预留最多75秒压缩准备窗口。目标摘要提前完成则立即启动；超时仍推进研究，只省略未完成文本。准备窗口持久化，重启不重新延长，也不消耗产品/周期调度间隔；新模型配置会重建准备窗口。正在执行的研究仍保留原截止，不补入晚到摘要。

POST /api/compression/news/{id}/reprocess 在 Session/CSRF 防护下为当前来源/模型生成新的任务代次，重新调用模型，旧输入输出均保留。新的部分或失败结果不会替换已完成摘要；新摘要只影响之后启动的研究。此操作不引用 SimulationLedger，也不调用任何订单接口。可重复执行不意味着摘要一致或没有调用成本。

说明：队列“摘要完成”仅表示格式、长度、分块完整性和版本检查通过，不证明内容无遗漏；公开 RSS 也不代表商业低延迟快讯。整个研究耗时和实测交易有效性仍需单独验收。

## 0.4.9 队列通知与停机归档

到达通知只唤醒独立扫描线程，批量更新合并为一次待执行扫描，采集线程和重新压缩接口不等待完整数据库扫描或模型请求。原始入库记录作为持久化队列的恢复来源，两秒扫描补偿通知窗口内的更新。关闭服务时中断请求并等待压缩任务归档完成，再退出执行器。

0.4.9 的准备窗口跟随压缩请求超时（1–300秒，默认75秒），避免在UI放宽请求超时后仍提前打断。准备完成或到达期限后，才冻结最新行情并开始研究有效期；上游超时明确归档并退避重试，预算不足与网络无响应分别记录。

0.7.0将压缩使用的compression_lane与fast/deep提供商许可、工作线程和失败状态隔离，停止研究抢占与前置等待。取消结果归档暂时清除并恢复线程interrupt标志，避免JDBC连接因取消中断；封存阶段和终态不被迟到结果改写。V4将归档通道数量及边界改为事务内增量维护，迁移回填只执行一次。
长短线的自动启动准备也分别排队，模型目录检查不会阻塞另一周期的启动；正在准备的产品/周期去重，只有实际启动成功才消耗调度间隔。

0.7.1兼容Any2API新目录：当available字段缺失且精确模型身份已cataloged时，允许请求进入独立执行池，界面标记“已列入目录，待真实调用验证”。显式不可用、旧版强制熔断及身份不符仍拒绝；目录准入不证明推理成功，完整SSE终态、格式校验、重试与各通道冷却继续决定真实结果。

0.7.2按真实MiniMax回复补充文本封装兼容：在显式protocol行之前允许最多2048字符的纯说明文字，原文仍完整归档；前缀中出现结构字段、JSON或代码围栏时拒绝，协议后的字段与尾文仍完整校验。财务数值、方向与引用不猜补，真实失败样本作为固定回归资料。
