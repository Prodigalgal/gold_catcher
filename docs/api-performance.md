# 页面读取性能与流式模型请求

0.4.10 使用 Redis 与有容量上限的本地 Caffeine 缓存。缓存仅用于界面展示：新闻列表与正文2秒、模型状态与最新研究1秒、压缩状态1秒、复盘5秒、不可变压缩详情5分钟。新提交的记录版本改变缓存键；时间戳仍取原始计算结果。Redis仅在集群内暴露，需独立Secret密码，不持久化，可随时丢弃；失败退避30秒，回退本地与数据库。当前单副本执行架构未改变。

0.4.11 将 Redis 连接超时设为1秒、命令超时500毫秒，分别可通过 `GOLD_CACHE_REDIS_CONNECT_TIMEOUT`、`GOLD_CACHE_REDIS_TIMEOUT` 配置。真实跨节点测量中，TCP连接约77毫秒，连接、认证及PING合计约231毫秒；原200毫秒窗口过紧。Redis优先与后端部署在同一节点以减少往返；状态页显示最近故障的异常类型和时间，不保存可能含凭据的异常消息。界面在实际数据加载完成后验收，包含模型表单展开后的上下文预算。

行情、报价来源、账户、成本、订单操作、认证及研究冻结证据直接读取原服务。缓存不可延长报价、交易证据或策略有效期。`/api/dashboard?view=overview|sources|research|trades|review|operations` 只加载相应页面所需的重型数据，未指定 `view` 的旧客户端仍获得完整视图。历史研究列表与复盘统计读小型索引；原始记录、提示词、输出和冻结证据保留，升级只补建索引。

`/api/performance` 需登录，返回当前进程每条路由最近128次请求的p50、p95、状态与压缩前应用字节数；不采集正文、凭据或任意查询值。SSE长连接不计入普通API延迟。浏览器界面的运行→系统页展示指标。`Server-Timing` 为首次写响应时的应用处理时长，完整时长见性能接口；外部网络及代理耗时需另测。

所有研究、裁决与压缩请求使用 `stream:true`、SSE Accept 及使用量请求。按原顺序接收思考、正文和原生工具参数，在1MB响应上限内合并为统一输出。只有完整结束帧、结束原因和业务字段校验均成功后才提交结果；心跳、部分文字与格式错误不能计票或生成订单。兼容供应商返回完整JSON的情形，仍校验结束原因。

请求配置的总超时覆盖等待首包和读取响应体，示例与新建角色默认300秒；UI已保存的配置优先，冻结任务保持原配置。120秒无任何响应字节视为断流；any2api自身的保活帧可保持连接。首包、空闲、总超时及不完整响应分别归档，失败取消HTTP Future并释放供应商执行位。首次请求获得完整配置时长，重试使用阶段剩余预算，不再提前把总阶段时间均分为三份。保活不能无限延长请求、阶段或整轮研究；交易有效期独立计算，过期研究继续分析但不能出单。

改版UI保留，补回冻结摘要核验入口、移动端布局及研究历史只在实际变化时刷新。发布后的真实同节点基准与浏览器验收记录存入忽略目录 `artifacts/ui-revision-review`；本地模拟数据检查不替代生产接口测量。

0.4.12 为 K 线 SVG 右侧价格轴保留完整空间，鼠标坐标按同一画布宽度换算。复核包括6个周期、4种屏幕宽度的价格标签边界，以及每个视图首根、中间、末根柱的完整 OHLC 悬停读数；不修改 Java 行情、指标或记账计算。
