# AI 运行配置

0.4.5 在「运行与配置 → AI 提供商与角色配置」中管理提供商、API 端点、密钥、长短线角色以及前置压缩，无需重新构建镜像。

## 保存与生效

- 短线、长线各配置三个辩论模型与三个裁决模型。同一阶段需要三个不同提供商和不同底层模型；跨阶段可以复用。默认 MIMO Pro、DeepSeek default、Grok 3 同时担任两类角色。
- 每席可修改字符、UTF-8 字节、输入估算、输出预留和超时。完整请求仍按目录容量和保守余量检查；增加配置不能证明上游容量更大。阶段截止与结论总期限仍然有效。
- 前置压缩固定提供商 `mimo`，可选择该提供商模型、预算并开关压缩。默认 Flash，压缩调用不计票。修改 mimo 的端点、密钥同时供新的压缩请求使用。
- 保存整个配置生成递增版本，持久化到 PostgreSQL。下一轮研究冻结该版本、角色、端点、预算和凭据；正在进行的研究不会中途改模型。研究记录归档公共路线与版本，不包含密钥或端点。
- 保存携带 `expectedRevision`。另一页面已经保存时返回 `AI_CONFIG_REVISION_CONFLICT`；需重新读取后修改，不静默覆盖。普通实时推送不覆盖表单中的未保存编辑。
- 添加提供商后填写端点与凭据，再分配模型；移除仍被选中的提供商会阻止保存。保留 mimo 供前置压缩使用。QWEN 在配置、路线与请求层继续禁用。

## 端点与模型目录

支持 `ANY2API` 和 `OPENAI_COMPATIBLE` 协议。端点可填 `https://example.com/v1` 或服务根地址，后端调用 `/v1/chat/completions`；不支持将密钥写进 URL 的用户信息、查询参数或片段。

any2api 使用逐模型详细目录能力，保留厂商参数映射、严格函数与预算判定。通用兼容接口使用 JSON 文本与 `max_tokens` 请求预留，返回仍由 Java 校验；请求该参数不能证明上游实际执行了上限。

点击「刷新已保存端点的模型目录」只查询目录，不发起推理。目录正常时提供模型建议和上游声明容量。通用兼容接口可选手动模型模式，以便对接未提供 `/models` 的端点；此模式明确显示未验证推理。目录存在、配置存在和真实推理成功是三种不同证据。

## 凭据与恢复

API Key 仅写入，保存后只返回 `credentialConfigured`，不回显原值。留空保留已有密钥，填写新值替换，勾选清除则禁用该凭据；清除后不会悄悄回退到环境变量中的旧 Key。浏览器不写入本地存储。

凭据以 AES-256-GCM、每次随机 nonce 加密后落库，配置事件只保存公共字段。独立的 `GOLD_AI_CONFIG_ENCRYPTION_KEY` 为32字节随机主密钥的标准 Base64，由 Kubernetes runtime Secret 提供，备份保存在「服务器管理」私密目录，与数据库备份分别保管。主密钥缺失时不能保存配置，错误密钥不能解密已保存凭据；不要在配置轮换时覆盖主密钥。

首次没有数据库配置时，使用后端环境中的路线与凭据作为初始值。首次 UI 保存会复制并加密这些凭据，此后数据库配置优先，容器重启继续恢复。

认证接口：`GET /api/ai/configuration` 读取公共配置；`POST /api/ai/configuration` 保存；`POST /api/ai/configuration/models` 查询目录。写请求要求现有 PoW 登录会话与 CSRF，不新增匿名配置入口。

## 0.4.5 本地验证

168项 Java 测试通过。基于封存生产公开快照的36次请求预算检查，最高占用89%，仍保留余量。React 正式页面和设计样例均完成类型检查与构建。

使用真实 PoW 登录和本地配置接口验证端点/密钥/模型保存、重复模型拒绝、刷新保留和实际进程重启恢复；使用明确标注的 UI 讨论样例验证三份裁决、少数意见、缺第三票和旧版记录，覆盖1440/768/375/320宽度，无页面脚本错误。隔离环境未发起模型推理或内部订单；这些结果不替代部署后的真实整轮研究。
