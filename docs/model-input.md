# 模型输入精简（0.7.5）

研究、质疑、修订与三方裁决使用 `GOLD_RESEARCH_V2` 输出协议。事实输入与归档数据分别处理，模型收到的事实只包含 `evidence` 与匿名 `peers`。

- 不发送文章、来源关联、消息、角色、候选或订单的 ID，不发送引用清单，也不生成 YAML 锚点编号。宏观表中的关联在 Java 内完成，再使用指标名称表达含义。
- 新闻数组只包含已经完成的压缩摘要字符串，不带标题、来源、日期、版本、哈希、处理状态等额外字段。摘要本身保留的事件时间、数值、条件与不确定性不再裁剪。
- 执行槽、阶段编号、尝试次数、请求流水号、截止时间、缺席名单、审计哈希与压缩覆盖计数不进入事实输入。当前研究任务、职责与格式纠正以简短可信指令表达；超时、重试、准入与过期检查由 Java 执行。
- 行情、指标、预期、修订、仓位、费用和规则中的金融事实保留，包括价格时间、新鲜度、日频/公开盘中区别、单位、未知成本与适用范围。金额、价格、数量继续使用原十进制字符串。

裁决不返回候选 ID，而是复制一个完整候选方案，或返回 `plan.action=WAIT`。Java 校验参数、风险与失效条件一致后计票，仍需至少三席有效独立裁决。价格、数量和条件不拼接、不平均。旧版归档和已封存的历史投票仍可读取。

管理已有模拟订单时，模型复制原仓位的 `target.side/type/quantity/leverage/entryPrice`。Java 在冻结账户内匹配这些财务特征并绑定内部订单；零匹配或多个匹配都会拒绝执行并返回格式纠正，不能猜选。请求追踪 ID 仍按既有约定保存在 HTTP 链路和服务端审计中。

压缩请求也只发送标题、来源文本或待合并摘要。分块编号、总块数、缓存标识及执行截止时间留在服务端。摘要规则语义不变，保留已完成 v5 摘要缓存，避免因请求封装精简触发全量重压缩。
