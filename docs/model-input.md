# 模型输入精简（0.8.0）

## 0.8.0 精细化处理

`ModelDataFlow` 为纯转换管线：边界投影 → 有效费用/规则 → 精确去重 → 重复数值核验 → 同一观点内部去重 → 适用口径说明 → 公共列 → 驱动分组 → 共享发布表结构。每步记录规则、变更字段、规范 JSON 字符数和 SHA-256，记录只保存在服务端，不进入模型上下文。

同一口径、单位、统计期与事件时点的预期只选一份。明确映射的一致预期优先，提供方自有预测保持独立含义；同质量同一时点的冲突值标为未知。实际发布值只使用截止前发布、收到且完成提取的版本；日频与盘中、名义与实际收益率分别保留。Java 实际采用的费率及有效 CFD 杠杆约束优先，原始规格留在归档。

只删除可核验的重复：相同产品字段、相同估值时点、已规范化预期的重复格式、SMA20/布林中轨相同计算值、完整修订明细对应的计数，以及同一观点内部已经完整表达的重复文字。独立 AI 观点、完整方案、独有风险与反证不合并。已压缩新闻仅去除完全相同的字符串，不再截短或重压缩。

模型输入超过预算时保留完整事实并阻止发送，不再通过截取理由前缀来丢弃尾部的反证或条件。MACD 信号线、ATR 百分比、成交量与高周期指标有各自用途，继续保留；较早的月度最新发布也不按“超过七天”机械删除。原始价格、数量、成交量和费用保持精度，派生指标沿用明确的八位展示舍入，完整计算值另存。

同一批 96 条历史首次尝试输入离线对比 0.7.5 投影，双方使用相同的现行传输编码，新增布局说明计入完整客户端请求。固定短线裁决样例从 **12,120 → 10,780 字符**，再省 **1,340（11.1%）**；96 条节省 **8.6%–12.5%，中位数 10.7%**。逐项核对报价、驱动值和完整候选方案，并完成 YAML/JSON 往返验证。部分历史请求曾被预算阻止；本测试没有发起新模型请求，字符数不等于 token 或费用。

本机本批数据的投影耗时中位数 13.7ms，最高 255.5ms（包含首次运行开销）；这不代表生产服务器或端到端模型延迟。重放入口和输入输出契约见 [数据流说明](data-flow.md)。

## 0.7.5 历史实现与测量

研究、质疑、修订与三方裁决使用 `GOLD_RESEARCH_V2` 输出协议。事实输入与归档数据分别处理，模型收到的事实只包含 `evidence` 与匿名 `peers`。

- 不发送文章、来源关联、消息、角色、候选或订单的 ID，不发送引用清单，也不生成 YAML 锚点编号。宏观表中的关联在 Java 内完成，再使用指标名称表达含义。
- 新闻数组只包含已经完成的压缩摘要字符串，不带标题、来源、日期、版本、哈希、处理状态等额外字段。摘要本身保留的事件时间、数值、条件与不确定性不再裁剪。
- 执行槽、阶段编号、尝试次数、请求流水号、截止时间、缺席名单、审计哈希与压缩覆盖计数不进入事实输入。当前研究任务、职责与格式纠正以简短可信指令表达；超时、重试、准入与过期检查由 Java 执行。
- 行情、指标、预期、修订、仓位、费用和规则中的金融事实保留，包括价格时间、新鲜度、日频/公开盘中区别、单位、未知成本与适用范围。金额、价格、数量继续使用原十进制字符串。

裁决不返回候选 ID，而是复制一个完整候选方案，或返回 `plan.action=WAIT`。Java 校验参数、风险与失效条件一致后计票，仍需至少三席有效独立裁决。价格、数量和条件不拼接、不平均。旧版归档和已封存的历史投票仍可读取。

管理已有模拟订单时，模型复制原仓位的 `target.side/type/quantity/leverage/entryPrice`。Java 在冻结账户内匹配这些财务特征并绑定内部订单；零匹配或多个匹配都会拒绝执行并返回格式纠正，不能猜选。请求追踪 ID 仍按既有约定保存在 HTTP 链路和服务端审计中。

压缩请求也只发送标题、来源文本或待合并摘要。分块编号、总块数、缓存标识及执行截止时间留在服务端。摘要规则语义不变，保留已完成 v5 摘要缓存，避免因请求封装精简触发全量重压缩。

## 同批归档数据离线重测

基于 2026-10-15 11:37（UTC+8）采集的 8 轮研究、96 条首次尝试请求，以旧版保存的完整请求重建计数为基准，用新版 Java 编码和输出协议重放同一批事实。部分旧请求曾在预算检查时被拦截，96 条不等同于 96 次实际模型调用。这里统计完整客户端 JSON 请求体的 Unicode 字符数，不是模型 token，也不是上线后的收益或稳定性证明。

选用上一轮实际已发送、重建字符数与记录一致的短线永续 Grok 裁决请求：

| 项目 | 0.7.4 | 0.7.5 | 减少 |
| --- | ---: | ---: | ---: |
| 完整输入 | 16,891 | 12,120 | 4,771（28.2%） |
| 新闻及其封装 | 751 | 182 | 569（75.8%） |
| 引用白名单 | 993 | 0 | 993（100%） |

新闻精华正文仍是原来的 173 字符。96 条请求节省 23.7% 至 30.5%，中位数 27.4%。其中 48 条近期 0.7.4 事实包节省 26.2% 至 30.5%，中位数 28.4%。所有新版事实包经 JSON/YAML 解码逐值核对。

当时还有一个已离线测量、尚未启用的无损选项（现已纳入 0.8.0）：将 CSV 相同列值提到表级公共值，本例可从 12,120 再降到 11,580，节省 540 字符（相对新版 4.5%），逐单元格一致。宏观与日历合计仍占 51%；若要更大幅度缩减，需要评估按周期筛选事实和合并口径说明的影响，不能直接删除数值或未确认的成本。

本轮缩减的是输入上下文。裁决复制完整方案可能增加单次输出长度，不能把输入字符节省比例当成总 token 或费用节省比例。
